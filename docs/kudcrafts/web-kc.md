# web-kc: the Kudcrafts web client

`web-kc/` is a separate web app (Vite + React + TypeScript + Tailwind v4) that replaces the stock
`web/` UI in our image. Upstream's `web/` is untouched, so rebasing onto new ntfy tags stays clean.

## What the server expects

The Go server embeds `server/site` (`//go:embed site`) and only serves these paths from it
(`server.go` `staticRegex`): `/static/*`, `/app.html`, `/sw.js`. Every single-segment path (`/`,
`/<topic>`, `/settings`) is answered with `app.html`, and `/config.js` + `/manifest.webmanifest`
are generated by the server. web-kc's build follows that contract:

| Build output (`web-kc/build`) | In `server/site` | Notes |
|---|---|---|
| `index.html` | `app.html` | renamed, exactly like upstream `make web-build` |
| `sw.js` | `sw.js` | service worker (web push, precache); precache manifest already says `app.html` |
| `static/kc/*` | same | hashed JS/CSS/fonts/sound (`build.assetsDir`) |
| `static/images/*` | same | icons, same paths as stock (manifest + notifications use them) |
| `config.js` | deleted | dev example only; the server generates the real one |

## Build steps

`web-kc/bun.lock` is committed; installs must be `--frozen-lockfile`.

In a checkout (local builds, `make`-style):

```sh
cd web-kc
bun install --frozen-lockfile
bun run build:site      # tsc -b && vite build, then scripts/to-site.ts:
                        #   build/index.html -> build/app.html, rm build/config.js,
                        #   rm -rf ../server/site, mv build ../server/site
```

In the Dockerfile web stage (`WEB_DIR=web-kc`), where the stage copies its own output to `/site`,
use plain `build` and do the rename yourself; `build:site` would move the output to `../server/site`:

```sh
bun install --frozen-lockfile && bun run build
mv build/index.html build/app.html && rm -f build/config.js && mv build /site
```

The stage needs bun 1.4 (`oven/bun:1.4-alpine`, or `npm i -g bun@1.4.0`); `bun.lock` pins the musl
native packages for rolldown / lightningcss / tailwind-oxide. `bun run test` is worth running there too.

Rollback: build with `WEB_DIR=web` (stock UI) or run the previous image. web-kc stores its own
state in IndexedDB `kc-ntfy` and localStorage `kc.*`, so the two UIs never read each other's data;
switching back just means signing in again on the stock UI.

## Server features it uses

- Login: `POST /v1/account/login` (Basic) -> token, `PATCH /v1/account/token` hourly, `DELETE` on sign-out.
- Topics: `GET /v1/catalog` (spec §3.1) when `enable_catalog` is on; falls back to `GET /v1/account`
  subscriptions grouped by app prefix (`facemap-orders` -> `facemap`) when the catalog is off/404.
- Access: ntfy answers 403 to a whole multi-topic stream/poll if any one topic is unreadable, so every
  topic is probed with `GET /<topic>/auth` first. Unreadable topics are left out of the stream,
  backfill and web push, shown with a lock, and (if user-added, not catalog-managed) can be
  unsubscribed. A stream refused before opening, or a 403 on poll, re-probes and refetches the account.
- History: `GET /<t1,t2,…>/json?poll=1&since=<now - history_days>` once per topic (anything older than
  24 h arrives read), then `since=<newest time>`. Local cache pruned to `history_days`; a missing or
  zero `history_days` is treated as 90, never as "keep nothing".
- Catalog: sent with `If-None-Match` (the server's ETag is a per-user view hash); 304 reuses the cached body.
- Live: one WebSocket `/<readable topics…,sync_topic>/ws?auth=…&since=…`; a `{"event":"sync"}` on the
  sync topic, every (re)connect and a 15-minute poll all refetch account + catalog (contract §14.3).
- Web push: `POST/DELETE /v1/webpush` with every readable topic except muted ones. The service worker
  reads topic titles, icons and sound classes from IndexedDB (written by the app), and shows
  priority ≤ 2 and `silent` topics without sound.
- Tokens: the login token is extended hourly with `PATCH /v1/account/token`, also in hidden tabs.
  Any 401 runs the same cleanup as sign-out: web push unsubscribed, cached messages cleared, query
  cache dropped. The IndexedDB cache (`kc-ntfy`) is tied to one username and cleared when another signs in.
- URLs from publishers (click, actions, attachments, icons, markdown links) are allowed only as
  http(s), plus mailto/tel for links; anything else (javascript:, data:) is dropped, in the app and the
  service worker.
- Publish: JSON `POST /` (topic, title, message, priority, tags, click, markdown).

## Develop

```sh
cd web-kc && bun install
bun run dev                 # Vite on :3000; edit public/config.js base_url to point at a server
bun run build && bun run mock   # built app + mock ntfy API on :4180 (login demo / demo)
bun run test && bun run typecheck
```

`dev/mock-server.ts` implements just the endpoints above with fixtures in `dev/fixtures.ts`;
`/__mock_login?next=/` signs in without a form (for screenshot agents). It is never built into the app.
The mock also keeps one unreadable subscription (`legacy-reports`) and answers 403 to any stream or
poll that includes it, like ntfy, to exercise the no-access path. `LOG=1` prints every request.

Code rule: no direct `useEffect`. Server data goes through TanStack Query, local history through
Dexie live queries, UI state through a small zustand store, and `useMountEffect` (in
`src/hooks/useMountEffect.ts`) only syncs external systems: the WebSocket, `matchMedia`, keyboard
listeners and the unread badge.
